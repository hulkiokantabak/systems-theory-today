ANCHORED SEVERITY GUIDE — for scoring flaws found in analytical documents
Self-contained. Read this in full before you score anything. It defines three severity bands, shows worked examples of each, and — most importantly — shows the BOUNDARY cases where two bands are easy to confuse. In prior rounds, coders agreed on severity at a rate near chance; almost all of that disagreement was at the boundaries, not the centers. This guide exists to fix the boundaries.

# 1. The three bands (definitions are fixed and may not be reworded)

The severity of a flaw is not how alarming it sounds. It is what the flaw does to the document's stated conclusion. Read each definition literally. These definitions are frozen: you illustrate them with the examples below, you never widen them, and you never soften a band to make two coders agree.

SEV: band=S3; label=high/critical; weight=9; definition="Would have changed a conclusion, shipped a false claim, or invalidated an output if uncaught (e.g. an invented citation, a wrong causal direction, a falsification condition that can't actually be checked; a resolved-away objection that was decisive)."
SEV: band=S2; label=medium/substantive; weight=3; definition="Materially weakens rigor but not the headline (e.g. an unstated assumption, a missing control, a strawmanned opponent, an unlabeled agreement-strength)."
SEV: band=S1; label=low/minor; weight=1; definition="Local slip (e.g. a stale cross-reference, a count mismatch, a typo in a claim)."

# 2. Two notes that ship inside this instrument (read them, do not skip)

CONFESSION: anchoring calibrates agreement among coders; it does not establish that criticality is found rather than made.

SIGNED-SCALE: the 1/3/9 weighting is a chosen ranking, not a discovered fact. Someone decided a critical flaw is worth exactly nine minor ones and three medium ones; a different, defensible scale would weight them differently and would re-order some totals. The scale privileges a loud, adversarial register of error — a fabricated source, a reversed cause — and structurally under-weights quiet failures whose damage is real but undramatic (see Section 5). Whoever sets the weights decides what counts as grave, and bears the responsibility if the weighting is wrong. Score the band honestly; treat the weight behind it as a value choice, not a law of nature.

# 3. The decision procedure (use this every time, in this order)

STEP-1: Restate the document's actual conclusion in one sentence — the headline it asks a reader to carry away.
STEP-2: Mentally CORRECT the flaw (state the missing assumption, add the missing population, fix the number, remove the fabricated source, name the silence).
STEP-3: Re-read the conclusion after the correction.
CUT-S2|S3: If the corrected version no longer follows — the conclusion flips, voids, or would have to be withdrawn — the flaw is S3. If the conclusion still stands but now rests on visibly weaker ground, the flaw is S2.
CUT-S1|S2: If correcting the flaw changes no number that feeds any claim and would mislead no careful reader about the substance, the flaw is S1. If it weakens the rigor or verifiability of a claim without overturning it, the flaw is S2.
TIE-RULE: If you are genuinely torn between two bands, do NOT round down as a reflex. Round down ONLY at the S1|S2 cut. At the S2|S3 cut, resolve it by re-running STEP-3: the question is strictly whether the conclusion survives correction — answer that, and the band follows. Rounding a conclusion-invalidating flaw down to S2 because it "reads calm" is the exact error this guide is built to stop.

# 4. Worked exemplars — at least three per band (all domains invented; none derived from any prior coder's verdicts)

## S1 — local slip (nothing that feeds a conclusion)
EX: band=S1; domain=epidemiology-summary; register=LOUD; excerpt="Background: the influenza pandemic of the last century is estimated to have killed 50,000,000,000 people worldwide, underscoring the value of early surveillance. This report summarizes influenza-like-illness counts from three district clinics for the most recent season."; flaw="'50,000,000,000' (fifty billion) is impossible — it exceeds any human population and should read ~50 million."; why="The figure sits in a scene-setting background sentence, feeds no calculation, and the report's findings concern clinic counts. Correcting it changes nothing downstream. Alarming magnitude, zero consequence — this is the model of a LOUD S1."; cat=CONS
EX: band=S1; domain=school-curriculum-review; register=neutral; excerpt="The reading-level methodology is described in Appendix B."; flaw="The methodology is actually in Appendix C; Appendix B holds the roster."; why="A reader spends ten seconds relocating it; no claim, number, or conclusion depends on the pointer. Stale cross-reference."; cat=CONS
EX: band=S1; domain=municipal-water-report; register=neutral; excerpt="We sampled 15 monitoring sites across the basin (abstract). ... Fourteen sites were sampled; site-by-site results follow (methods)."; flaw="Abstract says 15 sites; methods, every table, and all analysis use 14."; why="The analysis is internally consistent on 14; the abstract count is a typo that misleads no one about the result. Count mismatch, local."; cat=CONS

## S2 — materially weakens rigor, headline survives
EX: band=S2; domain=public-transit; register=neutral; excerpt="Weekday ridership rose 6% in the six months after the fare reduction. This is consistent with the fare reduction increasing ridership."; flaw="A new regional rail connection opened in the same window and is not accounted for (a missing control)."; why="The 6% rise is a real, correctly measured observation and the causal language is hedged ('consistent with'). Correcting — naming the confound — leaves the headline standing but weakens the attribution. Missing control, headline survives."; cat=EVID
EX: band=S2; domain=school-curriculum-review; register=neutral; excerpt="Opponents of structured phonics would have us believe children need no reading instruction whatsoever. Our trial shows structured phonics improved decoding scores by 11 points."; flaw="No opponent holds the attributed position — a strawman."; why="The trial evidence stands on its own; removing the strawman makes the argument fairer without touching the conclusion. Strawmanned opponent."; cat=FRAME
EX: band=S2; domain=clinical-meta-analysis; register=quiet; excerpt="Pooling the twelve trials, the review reports the evidence as consistent in showing the treatment shortens recovery, and recommends adoption."; flaw="Between-trial heterogeneity was high and three trials found no effect; describing the mixed body as consistent is an unlabeled (overstated) agreement-strength."; why="The pooled estimate may still support adoption on the weight of evidence; the flaw is presenting a heterogeneous, partly-null body as consistent agreement — an overstated agreement-strength that weakens rigor without flipping the recommendation. Note: this one is quiet in register but still S2 — quietness does not push it up, and overstated agreement does not by itself void a conclusion."; cat=FRAME

## S3 — would change a conclusion, ship a false claim, or invalidate an output
EX: band=S3; domain=pharmacology-review; register=LOUD; excerpt="Concurrent use of the two agents is safe at standard doses (Marlowe & Sant, 2019)."; flaw="No such study exists; the safety statement rests entirely on the fabricated citation."; why="Remove the nonexistent source and the safety claim is unsupported — the conclusion does not survive."; shipped="'Concurrent use is safe' — a false safety claim that would guide dosing."; cat=FAB
EX: band=S3; domain=urban-air-quality; register=neutral; excerpt="Days with more asthma emergency visits had higher particulate readings; we therefore recommend measures to reduce emergency-department load to improve air quality."; flaw="The causal direction is reversed — particulates drive asthma visits, not the reverse."; why="Correcting the direction voids the recommendation entirely."; shipped="An inverted causal claim and a policy that would spend money on emergency-department load and do nothing for the air."; cat=LOG
EX: band=S3; domain=hydrological-forecasting; register=quiet; excerpt="The model is considered validated; it will be deemed inadequate only if its operational performance is unacceptable."; flaw="'Unacceptable' is never defined, so no outcome can ever mark the model as failed."; why="A validation with no possible failure condition carries no information; 'validated' is empty as stated. RIDER — distinguish this from S2: this is S3 because NO correction can rescue the claim (there is no failure condition it could ever meet), so the output carries zero information. That is different from a real assumption that is merely under-justified but plausibly holds (S2, see the pension 6.5% boundary in Section 6). 'Unsupported' is not automatically S3; 'unfalsifiable, therefore empty' is."; shipped="'The model is validated' — presented as if it had passed a real test, licensing decisions built on it."; cat=LOG
EX: band=S3; domain=workforce-program-evaluation; register=QUIET/OMISSION; excerpt="Among participants who completed the twelve-week program, median earnings twelve months later were 22% higher than at intake. We conclude the program raises participant earnings."; flaw="The analysis silently includes only completers; the excerpt never states that a large share of enrollees left before completion and were dropped from the earnings comparison — and their outcomes are unmeasured and plausibly worse."; why="Account for the people who left and the basis for a claim about 'the program' (as enrolled) disappears; what survives is 'people who complete earn more,' which may reflect who completes, not what the program does. The flaw is a silence, not a statement — the population the conclusion does not cover."; shipped="'The program raises participant earnings' — a general claim contradicted by the omitted population. This is the gravest and most missable shape of S3: nothing on the page is wrong; what is missing is."; cat=FRAME
EX: band=S3; domain=hospital-quality; register=QUIET/OMISSION; excerpt="The share of operations with complications fell from 8% to 4% after the new protocol; we conclude the protocol made surgery safer."; flaw="Over the same period the hospital stopped accepting high-risk referrals, so the case mix shifted toward simpler operations; the change in who is operated on is nowhere mentioned — the denominator's composition changed underneath the rate."; why="Correct for the case-mix shift and the lower complication share no longer shows a safer protocol — it can reflect easier patients rather than better care; the conclusion does not survive. A second omission shape, distinct from the workforce case: there the excluded people were dropped from the numerator's population; here the comparison's denominator silently changed composition. Both are conclusion-voiding silences."; shipped="'The protocol made surgery safer' — a false claim that could spread an unproven protocol."; cat=EVID

# 5. Register warning (this is where prior agreement was worst)

RULE: Severity is not loudness. Two failure modes to guard against, in both directions:
QUIET-MISS: A one-clause silence — the population a claim quietly excludes, the standpoint whose absence flips the reading, the follow-up window that ends before the risk begins, the denominator that changed underneath a rate — can be S3 even though nothing on the page reads as an error. If correcting the silence would void the conclusion, it is S3, no matter how calm the prose. The workforce and hospital examples above, and the device-reliability boundary in Section 6, are the templates. A silence is not only an omitted sentence: an over-correction that quietly removes the very effect under study (see the mediator boundary logic) reads just as calm and is just as grave. Do not let an omission-shaped or quietly-stated flaw fall to S2 because you cannot point at a wrong sentence.
LOUD-INFLATE: A dramatic word, a huge number, or an alarming phrase in a place that feeds no conclusion is S1. The fifty-billion typo above is the template. Do not let a loud flaw climb to S3 because it startles you.
TEST: For every candidate, ask STEP-3 (does the conclusion survive correction) — never "how bad does this sound." The Section 6 register-cut pair works two quiet omissions side by side, one S3 and one S2, so you can see that the cut is set by STEP-3 and not by register.

# 6. Boundary pairs (the heart of this guide — anchoring the cuts, not the centers)

Each pair holds two flaws that look like the same band on the surface but sit on opposite sides of a cut. The lesson in every pair: the surface category and the surface register do not set the band — the cut test does.

## Cut S2|S3 by MAGNITUDE — same surface category ("unstated assumption"), opposite bands
BOUNDARY: cut=S2|S3; verdict=S2; reads-like=S3; domain=pension-projection; excerpt="The fund is projected solvent through 2060 under the base case."; flaw="The base case assumes a 6.5% nominal annual return, stated nowhere in the summary and unjustified, and the whole projection rests on it."; why-not-S3="6.5% is within the plausible long-run range for the stated asset mix; state and justify it and the solvency conclusion is intact. The flaw is under-justification (rigor), not a false claim. It READS like S3 because 'the entire conclusion depends on an unstated assumption' — but dependence on an assumption is only S3 when correcting the assumption breaks the conclusion."; cat=FRAME
BOUNDARY: cut=S2|S3; verdict=S3; reads-like=S2; domain=pension-projection; excerpt="The fund is projected solvent through 2060 under the base case."; flaw="The base case assumes a 13% nominal annual return, stated nowhere and unjustified."; why-S3="13% sustained is indefensible for the asset mix; correct it to a realistic 6-7% and the fund flips from solvent to insolvent well before the horizon. It READS like S2 because 'unstated assumption' is one of the S2 examples in the definition — the trap. The category is identical to the S2 case above; the magnitude is what invalidates the conclusion."; shipped="'The fund is solvent through 2060' — a false claim that would shape contribution and benefit decisions."; cat=FRAME

## Cut S2|S3 by REGISTER — two quiet omissions, opposite bands (this is the register cut where prior agreement was worst)
BOUNDARY: cut=S2|S3; verdict=S3; reads-like=S2; domain=medical-device-reliability; excerpt="Across the six-month monitoring period the implant recorded zero mechanical failures; the device is rated reliable for long-term use."; flaw="The failure mode of concern is fatigue fracture, whose documented onset is 3-5 years of loading; the six-month window ends long before any such failure could occur, and the excerpt never says so."; why-S3="Run STEP-3: correct the silence — note that the monitored window closes before the risk begins — and 'reliable for long-term use' has no support at all; zero failures in a window where failure is structurally impossible carries no information about long-term reliability. The conclusion does not survive. It reads like a calm, well-behaved S2 (a real observation mildly over-generalized), but it is S3: the observation cannot bear the conclusion."; shipped="'The device is reliable for long-term use' — a false safety claim licensing implantation."; cat=EVID
BOUNDARY: cut=S2|S3; verdict=S2; reads-like=S3; domain=soil-amendment-trial; excerpt="The amendment raised yield by 8% in our trial region; we recommend it for the crop."; flaw="The summary does not state that the headline figure is single-region, though multi-region replication reported in the appendix confirms the same direction and magnitude."; why-S2="Run STEP-3: correct the silence — state that the headline trial was single-region — and the recommendation still stands, because independent multi-region replication (present, in the appendix) supports it. The omission weakens the summary's self-sufficiency, not the conclusion. It reads like the device case (a quiet omission behind a broad recommendation, so it feels S3), but the conclusion survives correction because the missing support actually exists elsewhere in the document. LESSON: the two failures share the identical quiet register; the cut is set purely by STEP-3 — does correcting the silence leave the conclusion unsupported (device, S3) or merely remove a shortcut to support that is really there (soil, S2)?"; cat=FRAME

## Cut S1|S2 — a slip that propagates vs one that does not
BOUNDARY: cut=S1|S2; verdict=S1; reads-like=S2; domain=groundwater-survey; excerpt="Abstract: 15 monitoring sites. Methods and all tables: 14 sites."; flaw="A count mismatch between the abstract and the rest of the document."; why-not-S2="Every table and every calculation consistently uses 14; the abstract number touches no result. It READS like it might undermine rigor, but nothing propagates — a local slip."; cat=CONS
BOUNDARY: cut=S1|S2; verdict=S2; reads-like=S1; domain=clinical-effect-report; excerpt="Effect sizes were computed for the treated group as defined in Section 2.1."; flaw="The reported effect sizes actually correspond to the broader group defined in Section 2.2; Section 2.1 defines a narrower group."; why-S2="It READS like a stale cross-reference (S1), but a reader who follows the citation reconstructs a different group and cannot reproduce the reported number — the claim's verifiability is broken, not merely its signposting. The reported figure may itself be right, so the conclusion stands; the mis-pointer weakens rigor. That lift from S1 to S2 is the whole point of the pair."; cat=CONS

# 7. Coding rules

RULE: Score each flaw against Section 1's definitions using the Section 3 procedure. Anchoring examples illustrate the definitions; they never widen them.
RULE: An unsupported or under-justified claim is not automatically S3. It is S3 only when no correction can rescue it — there is no possible failure condition, or the support does not and cannot exist. It is S2 when the support is merely unstated or weak but plausibly holds. Distinguish "carries zero information" (S3) from "under-justified but defensible" (S2).
RULE: A quiet register never lowers a band and a loud register never raises one. Apply STEP-3 identically to a calm silence and to an alarming sentence.
RULE: Never revise a band definition, and never re-band an item, to make your score match another coder's. Agreement is an outcome of shared anchors, not a target you steer toward.
RULE: Ambiguous provenance (who or what surfaced the flaw) is not treated as structural; ambiguous severity is resolved by the cut test (Section 3), not by rounding.
RULE: Judge the flaw's effect on the conclusion by what is on the page, not by whether you find the conclusion congenial.

# 8. Response format (paste-robust — one record per line, keyword prefix, no tables)

Return exactly these lines, in this order, and nothing else:
- FIRST line: MODEL: identity="<state your model name and version in your own words>"; role=coder
- THEN one record per flaw or item (see below)
- LAST line: MODEL: identity="<state your model name and version again>"; role=coder

When scoring a free document, emit one record per flaw, each on a single line:
FORMAT: CATCH: id=<short-id>; quote="<verbatim span the flaw lives in>"; cat=<FAB|LOG|EVID|FRAME|CONS|MEAN>; sev=<S1|S2|S3>; conclusion-effect="<what happens to the stated conclusion if this is corrected>"; shipped="<if S3: the false claim that would ship uncaught; else: none>"

When scoring the calibration items, emit one record per item, each on a single line:
FORMAT: SCORE: item=<id>; sev=<S1|S2|S3>; note="<one line: what correcting the flaw does to the conclusion>"

PARSE-ROBUSTNESS (read this so your return scores correctly):
- Fields are separated by "; ". The note (or shipped) field is ALWAYS the final field on the line and is wrapped in double quotes; the line ends at its closing quote. A scorer reads it as note="(.*)"$ — so a semicolon INSIDE the quoted note is fine, but do NOT put a double-quote character inside the note.
- Echo each id EXACTLY as printed on the item sheet (e.g. G01, not 1, not g1).
- Emit one SCORE line per item, in printed id order, with no items skipped. A missing line is scored as a miss; a missing note parses as empty, not as an error.

Category legend (project-neutral; used only in the CATCH format, never in SCORE): FAB=fabricated/invented source, statistic, or attribution · LOG=logical/inferential (non-sequitur, wrong causal direction, unfalsifiable-as-stated) · EVID=evidential (missing control, cherry-pick, confounded comparison, over-claim beyond data) · FRAME=framing/scope (strawman, scope-creep, buried assumption, omitted standpoint/blind spot) · CONS=consistency (contradiction, stale cross-reference, count mismatch) · MEAN=meaning-boundary (measures only the measurable and declares the unmeasurable handled).
