# SEALED COUNT PREDICTIONS (R1.2 - sealed before gold inventories were drafted; produced by the design phase)

SEALED COUNT-PREDICTIONS (repo-side; registered BEFORE any gold inventory is drafted; derived from the definition's grammar alone; no range references, matches, or is set to catch any prior coder's return — prior counts are motivating history only, never a target).

TWO REGISTERS, EXPLICITLY SEPARATED:

A. GOLD counts — points, derived from the grammar (these bind the builders' seeding manifests):
- Standard seeded segment with N distinct flaw-objects each caught in-text and s seeded sharpenings that provably survive an earlier mark's minimal repair: gold = N + s exactly (a repair-changing sharpening IS a distinct flaw-object and is counted in gold; define N* = N + s).
- Propagation segment (1 wrong input caught, d downstream marks, plus r independent residual defects caught): gold = 1 + r.
- Restatement merge-test (1 flaw-object caught at m loci): gold = 1 event (loci recorded qualitatively; no numeric locus-count prediction is sealed — no locus-individuation rule exists, so locus tallies are audit trail, never pass/fail).
- Dense split-test (k distinct flaw-objects caught within ≤150 words): gold = k.
- Commitment-omission segment (M breached commitments + j seeded surface catches): gold = M + j; a multi-instance shortfall under one commitment sentence counts once in M.
- Zero-event clean segment (including loud-register clean and rebutted-objection clean): gold = 0.

B. CODER bands — declared noise allowances, labeled as priced noise, not derivation (these bind the blind-application check and nothing else): every segment type gets the uniform band [max(0, gold−1), gold+1]; clean segments get [0, 1]. The per-segment bands GOVERN; the whole-set figure is the arithmetic sum of the sealed per-segment bands and is DESCRIPTIVE ONLY — it never triggers anything.

BLIND-APPLICATION CHECK (the definition-layer acceptance test; sealed here together with a local span-hit rule so the check never runs on an unsealed matcher):
- A fresh, context-isolated instance receives ONLY the sealed guide + ≥3 gold segments chosen by pre-registered random draw, stratified to include ≥1 trap segment (dense split-test or restatement merge-test), ≥1 commitment-omission segment, and ≥1 clean segment. The builders never hand-pick.
- The DEFINITION RETURNS for redrafting (the instance is never blamed) if EITHER (i) the instance's counts fall outside the sealed coder band in the same direction on ≥2 of its segments (systematic divergence, not one-off noise), OR (ii) on any standard segment fewer than 2/3 of the gold events are hit under the local span-hit rule: coder quote located (after normalization) and expanded to its smallest enclosing sentence(s); hit iff the expanded extent overlaps any gold locus extent, and for omissions iff the coder's commitment quote resolves to the gold commitment sentence. Count-band conformance alone NEVER passes the check — identical counts over different events is disagreement wearing a matching total, and this check may not be passed by the one statistic the pre-registration bars from meaning agreement.
- Mandatory-hit discipline is separate from these bands: at run time, ALL parseable coders missing any one commitment-anchored omission gold posts the run as FAIL, reported as register-bias, regardless of every count statistic.
- Sequencing guard: this document seals the bands AND the local span-hit rule together, before any base segment is drafted; the full matching rule and floor are fixture-tested and sealed before the blind check runs (see gold plan §7).
