# PROVENANCE CODES — who or what, inside the text, caught the flaw

For every catch you log, record exactly one provenance code. Judge only from what is in the response's text.

| Code | Use when the flaw was caught by… |
|---|---|
| `STRUCT-POS` | one named voice/position engaging another's statement — the catch arises from the disagreement between distinct voices in the text |
| `STRUCT-LEARN` | an explicitly invoked prior rule, principle, or recorded lesson that the text applies to spot the flaw ("per the standing rule against X, this fails…") |
| `STRUCT-ADV` | an explicitly designated adversary/devil's-advocate role within the text |
| `SOLO` | a single voice correcting itself or the question with no staged opposition involved — including any catch in a single-voice response |
| `EXT` | material brought in from outside the text's own reasoning (a cited external source doing the catching) |

**Rules:** ambiguous provenance is never a `STRUCT-*` code — when torn between SOLO and any STRUCT code, record SOLO. A multi-voice response can still produce SOLO catches (a voice correcting itself); a catch counts as `STRUCT-POS` only when the *interaction between voices* is what surfaces the flaw.
